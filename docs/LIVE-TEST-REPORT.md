## 环境与测试结果

客户端为 Ubuntu 24.04 / WSL2 x64，Node.js 24.14.0，OpenSSH 9.6p1，官方 Claude Code 2.1.267。服务器为 1 vCPU、950 MiB 内存的现有 VPS。开始时可用内存约 704 MiB，负载约 0.07；转发不需要在服务器运行模型或新代理服务，未发现需要迁移服务器的资源瓶颈。

所有模型任务都在临时项目中执行。首次任务修正一个加法实现，执行 `node --test calc.test.mjs`，两项断言通过。Claude 的自动记忆写入位于独立测试配置目录。原有工作项目和原有 Claude 配置未被替换。

| 真实操作 | 测得结果 |
| --- | --- |
| Sonnet 项目任务 | `claude-sonnet-5`，63.189 秒，307 个流式事件，正常结束 |
| 首次任务第一个文本片段 | 启动后 38.896 秒；此前包含启动、连接和工具阶段，并非网络 RTT |
| Opus 恢复会话 | `claude-opus-5`，15.437 秒，12 个流式事件，没有工具调用，准确回忆前文 |
| Grep / Read / Edit 权限测试 | 20.646 秒；使用 `--permission-mode default`，官方结果记录 Edit 权限拒绝，目标文件字节不变 |
| TUI | 原生菜单、模型选择、Esc 取消、取消后回复和 `/exit` 均完成，退出码 0 |
| 自动化检查 | 20 项测试通过；类型检查、实际打包安装、生产依赖审计通过 |

连接跟踪覆盖 Sonnet 任务与 Opus 恢复两轮及其子进程：分别观察到 69 / 56 次 loopback 连接尝试，各一次 VPS SSH 连接，没有发现其他外部 IP 连接。这是特定配置与测试范围的观察结果，不能推广为所有 Claude 功能和任意项目配置的出口保证。

实际出口检查通过 TLS 验证，返回 IP 与 VPS 相同。无账号凭据的 `GET /v1/messages` 返回 405，验证了 API 的可达性；随后真实认证模型请求成功。三次 SSH 中断后的新 HTTPS 请求分别在 4.270、4.757、7.940 秒内完成。`curl` 请求网页登录页返回过 403，这不是浏览器或官方 CLI 登录的验收结果；本轮官方登录与模型调用均已成功。

## 发现的问题与处理

1. **构建目录残留。** 从旧架构切换后，直接运行测试会执行已经删除源码对应的 `dist/tests/*.js`，出现旧依赖缺失等错误。已让 `npm run build` 先清理 `dist`；原来的 20 项测试和真实安装包检查随后通过。此问题没有要求恢复旧依赖。
2. **代理环境可以被设置覆盖。** 在独立临时项目中，用官方 CLI 的 SessionStart hook 读取实际环境，确认项目设置可将 `HTTPS_PROXY` 替换为另一地址，并将 `NO_PROXY` 恢复为 `*`。随后用自签 CA 信任的本地 HTTPS 接口验证实际路由：项目代理收到了 1 次 CONNECT 和 1 次 HTTPS 请求；设为 `NO_PROXY=*` 后，接口仍收到请求而代理收到 0 次 CONNECT，确认请求绕过代理。两项专项测试均使用假凭据与本地假接口，没有使用 Pro 凭据。当前只修正文档中的保证范围，未把启动器改成系统防火墙。
3. **认证需要检查实际来源。** 本机同时存在第三方 API 设置和共享 Anthropic 认证配置。仅设置 `CLAUDE_CONFIG_DIR` 后，CLI 仍读取 `~/.config/anthropic` 的认证；同时隔离 `XDG_CONFIG_HOME` 后，才明确显示未登录。用户在独立配置中完成官方 Pro 登录后开始真实模型验收。凭据没有从 VPS 导出。
4. **WSL 与 Windows 的 SSH 配置不互通。** Linux `ssh` 无法直接解析 Windows 的 VPS 别名，Windows 动态转发监听也未通过 WSL loopback 探测。使用原生 Linux OpenSSH、独立配置与专用转发密钥后链路正常。新增密钥仅允许转发到目的端口 443，并禁止交互式 shell；服务端 host key 经已有受信 SSH 连接核对。没有修改用户已有 SSH 配置。
5. **官方 CLI 的版本限制。** 2.1.267 的模型菜单可用，但将 Opus 5.5 标为需要 2.1.280+。该限制来自官方客户端。此版本首次 TUI 引导还重复显示登录选项；确认现有 Pro 登录和真实请求成功后，仅在独立配置中记录完成引导，再完成 TUI 验收。升级官方 CLI 后应重新验证上述流程。

本机已准备独立入口 `~/.local/bin/claude-tether-pro`。在 WSL 的项目目录中运行它即可进入官方界面；参数直接传给 Claude，例如 `claude-tether-pro --resume SESSION_ID`。该入口使用单独安装的当前测试包、独立 Pro 配置、原生 WSL SSH 配置，并关闭客户端自动更新以保持本次测试版本。它是本机配置，不是发布包额外提供的命令。
