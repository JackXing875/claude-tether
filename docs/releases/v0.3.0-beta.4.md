# Tether v0.3.0-beta.4

Upgrade future releases with one command:

```bash
tether update
```

`tether update --check` reports whether an update is available without installing it. Beta installations receive newer beta or stable releases; stable installations remain on stable releases. An already-current installation is left alone.

## Install this release

Earlier versions need this one-time bootstrap:

```bash
npm install --global https://github.com/JackXing875/claude-tether/releases/download/v0.3.0-beta.4/claude-tether-0.3.0-beta.4.tgz
```

Reuse your existing `--prefix` if you installed into a custom npm prefix. Personal shell wrappers must pass `update` to Tether before any `--` separating Claude arguments.

## Behavior

- Download the prebuilt package and SHA-256 manifest from this repository's GitHub Releases over verified HTTPS.
- Verify integrity, install offline into a temporary prefix without npm lifecycle scripts, enforce Node engine requirements and check the candidate before replacing the current package.
- Preserve CLI and VS Code launcher paths, login profiles, SSH preferences and extension settings. Keep running sessions alive; open a new session after upgrading.
- Keep a previous-package backup, restore it if activation fails, reject simultaneous upgrades and clean up after ordinary cancellation.

The updater needs a writable global npm installation on Linux/WSL or macOS. It does not overwrite source checkouts, invoke sudo, update Claude itself or deploy to other machines. GitHub downloads use the host network and host HTTPS proxy settings, independently of Claude's SSH tunnel. Abrupt process/machine failure during the short activation step may require restoring the retained backup or reinstalling; see the [operations guide](../RUNBOOK.md#upgrade-and-uninstall).

## Validation

The automated suite covers release ordering/channel rules, integrity failures, real staged npm upgrades, preserved launchers/profile, cancellation, concurrent-update exclusion, rename rollback, TLS validation and bounded redirects/downloads. The package check exercises the shipped updater against the real prebuilt tarball and rechecks CLI and VS Code entry points. Existing transport/isolation tests remain part of release CI.
