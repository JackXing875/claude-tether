# Tether v0.3.0-beta.5

Fix CUDA initialization in isolated sessions on native Linux NVIDIA hosts. Beta.3/beta.4 could show every GPU in `nvidia-smi` while PyTorch failed with `CUDA unknown error`, because device discovery omitted the hyphens in `/dev/nvidia-uvm`, `/dev/nvidia-uvm-tools` and `/dev/nvidia-modeset`.

## Upgrade

```bash
tether update
tether --version
```

Then exit the old Claude session and start Tether again. Resume the conversation with `tether -- --continue` if desired. An existing namespace keeps its old device mounts even after the package is updated. For the VS Code adapter, restart the Claude process by reloading the remote window.

For a fresh installation or a version older than beta.4:

```bash
npm install --global https://github.com/JackXing875/claude-tether/releases/download/v0.3.0-beta.5/claude-tether-0.3.0-beta.5.tgz
```

## Changes and validation

- Match the real NVIDIA UVM/modeset device names and inspect mounted inodes with `lstat`, preserving existing character-device bind mounts while excluding symlinks and ordinary files.
- Keep network isolation, native device permissions and existing WSL GPU access. No whole-host `/dev` mount, driver change or additional privilege is required.
- Add a hardware-independent regression fixture that exposes real character devices under NVIDIA, WSL, AMD and DRM names, and checks discovery and mount arguments.
- Pass 46 automated tests, the packed installation/self-update check and the production dependency audit.
- On a native Linux server with RTX 3090 GPUs, compare the same PyTorch 2.7.1+cu126 environment: old isolation returned `cuInit=999` and CUDA unavailable; patched isolation returned `cuInit=0` and CUDA available. Direct external IPv4 remained blocked. The diagnostic did not allocate GPU tensors or run kernels alongside active workloads; see the [validation report](../GPU-LIVE-REPORT.md).

The updater keeps current sessions running. Jobs launched inside a Tether session still stop when that session exits; keep long-running schedulers in their existing host-managed session.
