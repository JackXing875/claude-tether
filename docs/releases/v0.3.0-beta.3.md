# Tether v0.3.0-beta.3

Use the official VS Code native panel through Tether and keep local GPU compute available in isolated mode.

## Changes

- Add `tether-vscode` for the official extension's `claudeCode.claudeProcessWrapper` setting. It uses the extension-supplied Claude binary and preserves SDK arguments, duplex stdio, working directory, permissions, cancellation and exit status.
- Restore GPU character devices in the otherwise minimal `/dev`, including WSL `/dev/dxg` and native NVIDIA/DRM/AMD nodes. Network isolation, blocked Windows interop and fail-closed behavior remain in place.
- Document Remote WSL setup, separate Pro profiles, GPU troubleshooting and the extension-host network boundary.

## Install

```bash
npm install --global https://github.com/JackXing875/claude-tether/releases/download/v0.3.0-beta.3/claude-tether-0.3.0-beta.3.tgz
```

Existing terminal commands, authentication profiles and preferences continue working. Start a new session after upgrading. Follow the [VS Code setup](../VSCODE.md) to enable the native panel; an ordinary terminal alias is not the extension wrapper.

## Validation and limits

34 local automated tests passed. The packed installation verifies `tether`, `claude-tether` and `tether-vscode`; the production dependency audit reported zero vulnerabilities. Real Pro tests with the extension's Claude 2.1.309 binary exercised file tools, SDK permission/hook/MCP callbacks, Sonnet-to-Opus switching and PyTorch CUDA compute while direct IP access remained blocked. See the [live validation record](../VSCODE-LIVE-REPORT.md).

Desktop panel rendering and interactions require separate acceptance after reload. The wrapper covers the child Claude process, not every request made by the VS Code extension host. CLI `/ide` host-loopback connections remain restricted. Native Linux GPU hardware and macOS/Windows-native compatibility were not validated. No identity spoofing or account-safety guarantee is included.
