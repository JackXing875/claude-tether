# Tether v0.3.0-beta.6

Keep network isolation while making host processes visible by default. Add read-only host inotify diagnostics and fix failures in HTTP forwarding, TCP half-close handling, custom temporary directories and concurrent self-updates.

## Upgrade

Default host process mode requires **Python 3.9+**, in addition to Linux/WSL, Node 24 and bubblewrap 0.9+:

```bash
# Ubuntu/Debian, if python3 is missing:
sudo apt-get install python3
tether update
tether --version
```

The expected version is `0.3.0-beta.6`. Existing preferences without a `processes` field select `host`; networking remains `isolated`. Start a new Claude or VS Code session to use the changes. Updating does not migrate or restart an existing session.

To retain the former private PID view, or to use isolated networking without Python:

```bash
tether setup --processes isolated
```

Use `tether setup --processes host` to restore the new default. A normal launch also accepts a one-time `--processes host|isolated` override. Custom shell launchers that classify flags must forward `--processes` as a Tether option, or use the setup command to save it. `--network proxy --processes isolated` is rejected.

Fresh installation:

```bash
npm install --global https://github.com/JackXing875/claude-tether/releases/download/v0.3.0-beta.6/claude-tether-0.3.0-beta.6.tgz
```

## Process tools and diagnostics

- Host PIDs are visible to tools such as `ps`, while user/network/mount restrictions and explicit GPU device mounts remain. Same-user host processes may be signaled where normal permissions allow; there is no extra host ptrace privilege.
- `tether doctor --inotify [--json]` reads current-user host watch records, actual kernel limits and incomplete-read counts. It works through a fixed read-only private IPC operation; it cannot run arbitrary host commands. Linux may still deny raw `/proc/<host-pid>/fdinfo` reads.
- A Python standard-library subreaper cleans this invocation's detached/double-forked descendants on normal exit and launcher death. Explicit PID isolation retains kernel namespace teardown. Directly killing the host supervisor can bypass its userspace cleanup; see [process boundaries](https://github.com/JackXing875/claude-tether/blob/v0.3.0-beta.6/docs/NETWORK.md#process-visibility-and-cleanup).

## Reliability fixes

- Invalid upstream HTTP statuses return 502 for the affected request instead of terminating Tether and Claude.
- Streaming GET/DELETE request bodies retain their framing; explicit content lengths remain intact.
- TCP write-half-closes during connection establishment preserve buffered uploads and the response direction.
- Unsupported ordinary HTTP Upgrade receives 501; unsolicited upstream 101 receives 502 and is cleaned up. HTTPS upgrades within CONNECT remain transparent.
- Private proxy, gateway and diagnostic sockets remain visible when `TMPDIR` is under `/run` or `/dev/shm`.
- Self-update rechecks the installed version under its lock and before activation, avoiding repeated installation or stale-list downgrades.

## Validation and remaining scope

All **75 automated tests**, the packed installation/self-update check and the production dependency audit passed. The packed candidate also passed real **Claude Code 2.1.310 / Pro** calls on WSL and native Linux: local tools, SDK permissions, host watch/GPU discovery, Sonnet-to-Opus switching, native CLI resume and normal descendant cleanup. The native `/model` menu, input cancellation and normal terminal exit were checked. See the [live report](https://github.com/JackXing875/claude-tether/blob/v0.3.0-beta.6/docs/PROCESS-MODE-LIVE-REPORT.md) and [development log](https://github.com/JackXing875/claude-tether/blob/v0.3.0-beta.6/docs/DEVELOPMENT-LOG.md).

SDK transport was tested with the official extension's binary; rendered VS Code panel interactions were not retested. GPU checks discovered devices/driver availability without allocating tensors or starting training. Real-account fault injection and long-duration recovery remain unverified. P3 release-workflow idempotency/concurrency work remains deferred. This is a beta release and does not provide an account-safety guarantee.
